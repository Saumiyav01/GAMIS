# GAMIS Architecture

Implemented local architecture through P5. Later aggregation, API, and evaluation phases are not included;
see IMPLEMENTATION_STATUS.md.

## Trust boundaries
```
User mission -> Supervisor (proposes) -> Authority Service (validates, signs) -> Worker (LLM, untrusted)
Worker -> Secure Tool Gateway -> registered synthetic adapters
Gateway/Supervisor/Workers -> Audit Ledger (append-only, hash-chained)
Gateway receipts -> Evidence Store -> Supervisor report
```
- The LLM is never the authority for its own permissions. Authority decisions are made by deterministic code.
- Tool outputs are untrusted data and can never alter assignments, permissions, budgets, goals, or policy.
- READ and ACTION are separate permission classes; ACTION is disabled by default.
- The limits of prompt-injection defence are stated honestly: the goal is to show injected text cannot
  **expand authority**, not that injection cannot occur.

## Implemented module boundaries (backend/gamis)
`schemas` and `security` (P1) · `audit`, `storage`, `evidence` (P2) · `authority` (P3) ·
`gateway` (P4) · `llm`, `agents`, `runtime`, synthetic `tools` (P5) · `evaluation` (P0).

## P0 foundation
- `tools/mock_tools.py` — deterministic in-memory doubles for the three tool names. **Doubles enforce no
  governance**; they are not the controlled tools.
- `tools/failure.py` — call-count-driven failure injection (timeout, error, malformed).
- `evaluation/` — seed loader/validator, scenario builder (investigation, attack, failure), harness,
  and two throwaway self-test systems.
- `backend/seeds/` — synthetic logs, intel, investigations, attacks, failures (generated by `scripts/generate_seeds.py`).

## Local runtime boundaries and limitations
- Runtime and gateway persistence use SQLite. Grant execution status is checked from durable SQLite state, not
  the P3 in-memory status helper.
- Each completed worker task writes a signed P2 EvidenceBundle linking structured claims to the evidence items
  and gateway receipts used to produce them.
- Development signing keys are stored outside the source tree; no hardware-backed key manager is included.
- Only synthetic tools and datasets are wired. The ACTION adapter remains disabled.
- A production human-approval channel is not included; ACTION is not enabled by the local demo.
- Frontend is a build-ready shell only; aggregation (P6+), API, and further phases remain unimplemented.
